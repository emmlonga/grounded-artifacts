# Artifact brief: alignment-stage commercial proposal (public example)

<!-- Filled from templates/artifact_brief.md. Generalized from the original run's brief. -->

| Field | Value |
|---|---|
| Artifact type | Commercial alignment proposal; not the definitive proposal |
| Mode | commercial-proposal |
| Maturity | alignment |
| Intent | Commercial qualification: validate direction before investing in a definitive proposal, executive presentation, acceptance package and contract |
| Objective | After reading, the buyer can explicitly validate six points: (1) whether this is the capability it wants in-house; (2) whether the initial scope is relevant; (3) whether building what differentiates and reusing market components makes sense; (4) whether the delivery sequence meets expectations; (5) whether the investment is within an acceptable order of magnitude; (6) whether any mandatory integration, security or operating requirement changes the design |
| Primary audience | The buyer's decision-maker: commercially sophisticated, non-technical; must understand the offer without reading the technical plan; may forward it internally |
| Evaluation criteria | Business-first; concise; commercially concrete; understandable without the technical plan; explicit about what is bought; transparent about initial scope and boundaries; precise enough to test real purchase intent |
| Secondary audiences | The buyer's legal and IT reviewers |
| Page budget and binding unit | About 5 pages; binding unit: rendered pages |
| Render profile | plain |
| Writer | default (commercial-proposal: none) |
| Sources | S1 commercial document: governs commercial framing, value proposition, packaging, stages, pricing, payment, responsibilities, stage-3 support, ownership in customer terms. S2 implementation plan: governs product truth, workflow, supported inputs, calculation scope, exclusions, trust boundaries, human review, security and data assumptions, dependencies. S1 governs only where compatible with S2; a commercial simplification never widens an S2 limit; apparent conflicts are recorded, not reconciled. One further annex excluded |
| Fixed values | none beyond the sources |
| Candidate framings | A: not another off-the-shelf tool; B: build what differentiates, reuse what does not; C: the owned asset is broader than the calculation engine; D: reviewed use creates an operational asset; E: the first release is bounded, not generic |
| Owner guardrails | No competitor claims; do not redesign or improve the offer; no "moat"; no automatic-learning claims; internal vocabulary kept out of the body |
| Confidentiality | The proposer's own proposal to the client; no anonymization map |
| external_audit | allowed |
| Required elements | the commercial-proposal mode's MUST INCLUDE list; closing alignment questions |
| Downstream use | Basis for the definitive proposal, executive presentation, acceptance package and contract |
